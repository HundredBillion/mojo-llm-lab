# Consistent Qwen3.5-2B CUDA/Mojo comparison

Both benchmark arms must load the same verified Qwen3.5-2B Q4_K_M file and use identical engine, cache, thread, batching and thermal settings. The existing 4B kernel is incompatible; zero replaced launches cannot count as Mojo evidence.

Implement a separate 2048-wide, 6144-row Q4_K gate/up specialization, retaining the qualified reduction structure and existing tolerance. The observer selects a fixed supported layout, and the runner rejects a mismatched PTX specialization. Validate real-model inputs before consuming candidate outputs. Preserve unsupported-call CUDA fallback and keep experimental replacement opt-in.

Run gates sequentially: compile/ABI checks; observe native specialization; shadow correctness; feedback/generated-output checks; bounded matched decode timing. Retain failures and stop on existing thermal/power limits. Identical models are necessary but do not eliminate clock, scheduling or short-window variation. Claim a whole-model gain only if repeated matched comparisons support it; otherwise report the remaining uncertainty.

The user separately has been asked whether the model switch should also change the application's normal local-server default. Benchmark adaptation does not depend on that answer. Production changes are not required to establish a consistent comparison.
